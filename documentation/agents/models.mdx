An agent names its models as `{provider, model}` pairs. The only valid pairs are the ones in the provider catalog, and a config naming anything else is refused on save with the list of what it could have said instead.

The catalog is live. `GET /v1/catalog` is authoritative; the tables at the bottom of this page are a snapshot of it and can lag behind.

<CodeGroup>
```bash cURL
curl https://api.in.talqing.com/v1/catalog \
  -H "Authorization: Bearer $TALQING_API_KEY"
```

```typescript TypeScript
const catalog = await talqing.catalog.get();

for (const entry of catalog.llm) {
  console.log(entry.provider, entry.model, entry.reasoning_efforts, entry.vision);
}
```

```python Python
catalog = talqing.catalog.get()

for entry in catalog["llm"]:
    print(entry["provider"], entry["model"], entry["reasoning_efforts"], entry["vision"])
```
</CodeGroup>

The response carries one array per kind — `llm`, `stt`, `tts`, `realtime`, `avatar`, `noise_cancellation` — plus `providers`, the union of every `language` an agent may be set to, the subset of those the turn detector understands, `system_vars`, and the platform fee per channel.

One provider's models are deliberately **not** in those arrays. A `providers` entry whose `browse` is `search` reaches hundreds of models through a single key, and shipping them all in this response would multiply its size; they are searched a page at a time instead, and its `searched_kinds` says which kinds (`llm`, `stt`). See [OpenRouter](#openrouter) below.

<Warning>
Every model runs on **your** provider key. An agent will not publish until a key is configured for each provider it needs — the language model, the speech models, the avatar, the noise canceller, and any fallback among them. See [provider keys](/get-started/provider-keys).
</Warning>

## Two pipelines

A voice or video agent runs one of two shapes, and `config.realtime` is what discriminates them. Set it, and it is the whole pipeline; leave it null, and the cascade runs.

| | Cascade (`stt` → `llm` → `tts`) | Realtime (speech-to-speech) |
| --- | --- | --- |
| Models | three, mixed freely across providers | one |
| Latency | three network hops per turn, one of which is the model | one socket, lowest time to first sound |
| Turn detection | ours, from the speech-to-text model and the language | the provider's, inside its own socket |
| Voice | any voice from any text-to-speech provider | the model's own roster |
| Fixed wording | the greeting, a `say` operation and a handoff message are spoken word for word | delivered as "say this" instructions the model may reword |
| `reasoning_effort`, `priority`, `builtin_tools` | yes | no |
| `fallback` | yes, per stage | no |
| Preemptive generation | yes | no, pinned off |
| `on_user_turn_completed` hook | yes | refused |
| Screen share | yes | refused |
| Expressive delivery | on the two models that speak tags | no |
| Recording consent notice | yes | refused |
| Images people attach | if the model reads images | if the model reads images — the two `grok-voice-*` entries do not |

**Take the cascade unless latency is the product.** It is the shape everything else on the platform is built around: exact wording, per-stage failover, provider-side tools, a screen the agent can watch, and one hook that fires on every user turn. What you pay for it is a longer path to the first syllable.

**Take a realtime model when the conversation is the interface** — a demo, a companion, an interview — and when you can live with a greeting that is approximate and a call that has no failover. A realtime agent still records, still analyses, still runs tools, MCP servers and handoffs.

Switching between them is a normalization, not an error: setting `realtime` clears `stt`, `llm` and `tts`, and setting them back means also setting `realtime` to null. See [channels](/agents/channels).

### The fields on each slot

| Slot | Fields |
| --- | --- |
| `stt` | `provider`, `model`, `fallback` |
| `llm` | `provider`, `model`, `reasoning_effort`, `priority`, `builtin_tools`, `fallback` |
| `tts` | `provider`, `model`, `voice`, `speed`, `expressive`, `stability`, `similarity_boost`, `fallback` |
| `realtime` | `provider`, `model`, `voice`, `speed` |

`voice_name` also exists on `tts` and `realtime`. It is a display label for the dashboard and is ignored when the agent is compiled.

`speed` accepts 0.5 to 2.0 as a number, and is then checked against the chosen model's own range — the tables below carry it. A model with no speed control refuses anything but `1.0`. Leaving `voice` null uses the entry's default voice. `stability` and `similarity_boost` belong to the ElevenLabs voice you picked and are refused on every other provider; see [voices](/agents/voices).

## Choosing

The language is the first constraint, not the last. Pick the language, then models that cover it — a model that publishes languages and does not speak the one you chose is a save error, and a model with `language_required` refuses Auto outright. See [language](/agents/language).

After that:

- **Speech-to-text is the biggest lever on how the agent feels.** A `streaming` model ends the turn on its own detector; a batch model transcribes each utterance in one request, which is cheaper and adds roughly half a second before the agent replies. Word-count interruption also stops working on a batch model, because there are no interim transcripts. See [speech-to-text and turn detection](/agents/speech-to-text-and-turn-detection).
- **The language model is where thinking time is spent.** On a call, every second of reasoning is silence — take the least the model will accept. See [thinking and provider tools](/agents/reasoning-and-builtin-tools).
- **Text-to-speech is where the agent's character is.** Price per character ranges over a factor of twenty-five across this catalog, and the two models that speak delivery tags are the only ones [expressive delivery](/agents/expressive-delivery) works on.
- **Mixing providers is normal.** The three cascade slots are independent, and the agent's single `language` is translated into each provider's own spelling for you.

### The priority lane

`llm.priority` asks the provider to schedule this model's turns ahead of standard traffic, which steadies the worst case rather than speeding up the average. It costs between 1.75x and 2.5x the standard token price depending on the model, so read [the priority lane](/agents/priority-lane) before switching it on.

### OpenRouter

[OpenRouter](https://openrouter.ai) is a gateway rather than a vendor: one key reaches roughly 260 tool-capable language models from about thirty labs — Anthropic, Meta, DeepSeek, Qwen, Moonshot, Mistral, Z.AI and the rest, alongside the OpenAI and Google models listed above. Save an OpenRouter key under [provider keys](/get-started/provider-keys) and every one of them becomes a legal `llm.provider` / `llm.model` pair.

Because the list is that large and moves that often — roughly six models a week — OpenRouter's models are not in `GET /v1/catalog`. Search them instead:

<CodeGroup>
```bash cURL
curl "https://api.in.talqing.com/v1/catalog/models?q=claude" \
  -H "Authorization: Bearer $TALQING_API_KEY"
```

```typescript TypeScript
const page = await talqing.catalog.models.search({ q: "claude", limit: 20 });
for (const entry of page.models) {
  console.log(entry.model, entry.context_length, entry.pricing);
}
```

```python Python
page = talqing.catalog.models.search(q="claude", limit=20)
for entry in page["models"]:
    print(entry["model"], entry["context_length"], entry["pricing"])
```
</CodeGroup>

With no `q` the results are ordered by how much traffic each model actually handles, so the first page is the models people run rather than the ones that sort first alphabetically. `next_cursor` pages through the rest. Set the `model` on your agent to the exact slug the search returned — `anthropic/claude-haiku-4.5`, `deepseek/deepseek-v4-flash`, `meta-llama/llama-3.3-70b-instruct`.

**What is listed.** Every model that outputs text and supports tool calling. That second filter is mostly a modality filter: it removes music, image and translation models, classifiers, and the bare completion models no agent could use. Four kinds of slug are excluded on purpose:

| Excluded | Why |
| --- | --- |
| `…:free` | Request-capped per day against your account's lifetime spend. A published agent must not stop working because your workspace crossed a line nobody set. |
| `…:batch` | Asynchronous. There is no live turn to serve. |
| `~author/model-latest` | A moving target. Publishing freezes an agent so a version means something, and a slug whose model changes underneath makes the version diff a lie. |
| `openrouter/auto` and the other router slugs | The model that runs is not the model you configured. Use `llm.fallback`, which names a real model on each side. |

**Thinking.** `reasoning_efforts` is built from what each model reports it accepts, intersected with Talqing's own vocabulary — OpenRouter's `xhigh` and `max` sit above `high` and are not offered, because nothing running a voice agent wants them. `none` is added wherever thinking can be switched off at all, and it is the default, so a Claude agent does not pause on every turn. Around a quarter of these models cannot stop thinking; the editor says so under the model.

**Images.** `vision` here comes from the model's declared input modalities rather than from a probe of our own, which is the one place in this catalog that is true. It is safe because the failure is loud: OpenRouter answers an image sent to a text-only model with a `404`, so a wrong flag produces an error naming the cause rather than a model that quietly answers about a picture it never saw. As everywhere else, `vision: true` means the model *can* read an image, not that it will read it correctly.

**Price.** The rates in the search results are the *cheapest* host's, and OpenRouter picks a host per request — the same model measured 2.4x apart on two consecutive calls. So on Automatic the editor's estimate is a floor; with [hosts](#hosts) chosen it is priced at the dearest of them, and is a ceiling. Your invoice is not an estimate: every OpenRouter line is priced from the exact charge OpenRouter reported for those requests, which you can reconcile against your own OpenRouter activity page.

**Routing.** Talqing sends two routing preferences on every request and neither is configurable. Requests are sorted by latency, because the default price-balanced routing was measured taking 88 seconds to answer "what is the capital of France?"; and hosts that train on prompts are refused outright. See [data retention and privacy](/platform/data-retention-and-privacy).

#### Hosts

OpenRouter serves each model from several hosts — Groq, Cerebras, DeepInfra, Azure and so on — and they differ a lot in speed: on `openai/gpt-oss-120b` the fastest answers in under 200 ms and the slowest in about two seconds. `llm.hosts` restricts a model to the hosts you name. Only those hosts will serve it, the fastest of them answers each request, and if one fails mid-request OpenRouter moves to the next within the same request. Leave it unset (Automatic) to let any host serve. `llm.fallback` and `analysis.model` each take their own; post-call analysis that follows the agent's model follows its hosts too.

The valid values are the `host` of each entry in the model's host list, fastest first. Latency and throughput are filled in when the workspace has an OpenRouter key:

<CodeGroup>
```bash cURL
curl "https://api.in.talqing.com/v1/catalog/models/hosts?model=openai/gpt-oss-120b" \
  -H "Authorization: Bearer $TALQING_API_KEY"
```

```typescript TypeScript
const { hosts } = await talqing.catalog.models.hosts({ model: "openai/gpt-oss-120b" });
for (const host of hosts) {
  console.log(host.host, host.latency_p50_ms, host.pricing);
}
```

```python Python
page = talqing.catalog.models.hosts(model="openai/gpt-oss-120b")
for host in page["hosts"]:
    print(host["host"], host["latency_p50_ms"], host["pricing"])
```
</CodeGroup>

```json
"llm": {
  "provider": "openrouter",
  "model": "openai/gpt-oss-120b",
  "hosts": ["groq", "cerebras/fp16"]
}
```

- **A host that stops serving the model is skipped.** The turn moves to `llm.fallback` only when *none* of the hosts can serve it. Publishing warns about each host that no longer serves the model, and refuses when none does.
- **Some hosts are never listed**: those whose policy is to train on prompts, which Talqing's routing would refuse anyway; endpoints that cannot call tools; and OpenRouter's queued `/flex` tier, which trades latency for price.
- **A host's bare name covers all its endpoints.** `azure` matches `azure/us` and `azure/eu` too, which is why the editor labels it "Azure · All endpoints" when it is listed beside them. Service tiers such as `openai/fast` are matched only when named in full.
- **Speech-to-text has no host selection.** OpenRouter's transcription endpoint ignores routing preferences.

**Not available here.** OpenRouter models take no provider-side tools and no priority lane — those are properties of a vendor's own API, and this is a gateway. Everything else works: fallbacks, handoffs, tasks, tools and post-call analysis.

The same key also reaches OpenRouter's speech-to-text models — see [below](#openrouter-speech-to-text).

#### OpenRouter speech-to-text

The same [OpenRouter](#openrouter) key reaches about twenty speech-to-text models — Whisper, Deepgram Nova-3, NVIDIA Parakeet, Qwen3 ASR, Voxtral, Grok STT and more. Like its language models they are searched rather than listed, with `kind=stt`, and every result is a legal `stt.provider: "openrouter"` / `stt.model` pair:

<CodeGroup>
```bash cURL
curl "https://api.in.talqing.com/v1/catalog/models?kind=stt&q=whisper" \
  -H "Authorization: Bearer $TALQING_API_KEY"
```

```typescript TypeScript

```

```python Python
page = talqing.catalog.models.search(kind="stt", q="whisper")
```
</CodeGroup>

What differs from the table above:

- **Every one is batch.** OpenRouter has no streaming transcription, so each utterance goes out as one request after the caller stops speaking. On a 4.6-second utterance that added between 0.6 and 3.4 seconds before the agent could reply, depending on the model; `openai/whisper-large-v3` took 11.6 seconds, and the editor says so under it. What they buy is price: the cheapest are about $0.012 per hour of speech, a tenth of the cheapest streaming model here.
- **A fallback must be another batch model**, because one voice detector ends every turn for both. That means `xai/xai-stt-batch`, `raya/bakbak-stt`, `elevenlabs/scribe_v2`, `openai/gpt-transcribe` or another OpenRouter model. A Deepgram, Soniox or Sarvam fallback is refused at publish.
- **The language is always detected.** OpenRouter publishes no language list per model, and a code a model does not really support comes back as a transcript in the *wrong* language rather than as an error. So none is ever sent. `config.language` still sets text-to-speech and turn detection; the transcription detects for itself.
- **Price.** The listed rate is the cheapest host's, and the invoice uses what OpenRouter reported charging per request — the same model measured 3.3x apart on identical requests. `openai/gpt-4o-transcribe` and `openai/gpt-4o-mini-transcribe` are priced per token, so the editor shows no per-minute estimate for them.
- **Privacy.** OpenRouter ignores routing preferences on this endpoint, so the no-training policy Talqing sends with every language-model request does not reach it. See [data retention and privacy](/platform/data-retention-and-privacy).

`openai/gpt-transcribe` exists twice: as `openai` + `gpt-transcribe` in the table above, on your OpenAI key and billed by OpenAI, and as `openrouter` + `openai/gpt-transcribe`, on your OpenRouter key. They are separate selections and never collide, but they read almost the same in a dropdown.

<Warning>
`openai/gpt-live-1` is the one model here with two caveats of its own.

It **cannot be handed off from.** The model refuses new instructions once a call is connected, and a handoff is exactly that, so an agent that names this model and a handoff destination is refused on save.

Its **$0.05/min is not the whole bill.** GPT-Live runs its reasoning and every tool call on a second model — `gpt-5.6-luna` — billed separately at that model's own per-token rates. Both appear on the call, the session minutes as a realtime line and the reasoning as an LLM line.

</Note>

### Noise cancellation

Voice and video only, off unless you turn it on, and it needs an ai-coustics key like any other provider. `enhancement_level` runs 0.0 to 1.0 and defaults to 0.8.

| Provider | Model | What it does |
| --- | --- | --- |
| aicoustics | `quail_vf_s` | Isolates the one person talking to the agent, suppressing other voices, echo and background noise. |
| aicoustics | `quail_vf_l` | The larger Voice Focus model — same job, significantly more CPU, no documented accuracy gain. |
| aicoustics | `quail_l` | Keeps every voice and removes only noise — a speakerphone, a room, a distant speaker. |
