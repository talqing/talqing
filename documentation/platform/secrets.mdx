---
title: "Secrets"
description: "Workspace credentials a tool can send but the model never sees. Write-only, referenced as a template, and never silently empty."
---

A secret is a named value stored encrypted in your workspace and read only by the runtime. Tools and integrations reference it as `{{secrets.NAME}}`; nothing ever hands the value back to you, to the model, or to the caller.

This is where every API key, bearer token, webhook signing key and carrier password your agents need belongs.

## Storing one

**ADMIN only.** In the dashboard it is **Build → Secrets**; over the API it is `POST /v1/secrets`.

<CodeGroup>
```bash cURL
curl -X POST https://api.in.talqing.com/v1/secrets \
  -H "Authorization: Bearer $TALQING_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "CRM_API_KEY", "value": "your-crm-api-key" }'
```

```typescript TypeScript
const secret = await talqing.secrets.create({
  createSecretRequest: { name: "CRM_API_KEY", value: process.env.CRM_API_KEY! },
});

console.log(secret.name, secret.value_hint); // CRM_API_KEY …9f2c
```

```python Python
import os

secret = talqing.secrets.create(name="CRM_API_KEY", value=os.environ["CRM_API_KEY"])

print(secret["name"], secret["value_hint"])
```
</CodeGroup>

### The naming rule

A name must match `^[A-Za-z_][A-Za-z0-9_]*$` — letters, digits and underscores, never starting with a digit. That is exactly the identifier shape the `{{secrets.NAME}}` token parses, so a name that cannot be referenced cannot be stored. A dash, a space or a dot is refused.

Names are case-sensitive and unique in the workspace. `SCREAMING_SNAKE_CASE` is the convention everywhere in these docs; nothing enforces it.

A value is 1–16,384 characters. An empty value is refused.

## Write-only

A stored secret is never returned by any endpoint, to anyone, including the ADMIN who stored it. A read gives you the name and a masked tail:

```json
{
  "items": [
    {
      "id": "0f4c2b1e-6a3d-4f18-9c77-2b81aa5d0e93",
      "name": "CRM_API_KEY",
      "value_hint": "…9f2c",
      "created_at": "2026-08-11T10:02:41.220Z",
      "updated_at": "2026-08-27T14:36:08.915Z"
    }
  ],
  "has_more": false,
  "limit": 200,
  "offset": 0
}
```

`value_hint` is the last four characters and nothing more — enough to tell two keys apart when you are rotating one, never enough to reconstruct either. Any member can read this list; only an ADMIN can write it. There is no export, no reveal button and no support path that prints a value back to you. If you have lost the original, store a new one.

## Where a secret resolves, and where it does not

| Place | Reads `{{secrets.NAME}}`? |
| --- | --- |
| A tool operation's URL, query, body and headers | Yes |
| Any other templated string in a tool's [operation tree](/tools/operation-tree) | Yes |
| An [integration's](/integrations/connecting) credential fields | Yes |
| An inline MCP server's URL and headers | Yes — and **only** `{{secrets.NAME}}`; every other root is a publish error there |
| A [carrier account's](/telephony/carrier-accounts) credential fields | Yes |
| An agent's **prompt** or **greeting** | **No.** A publish error |
| A [`code`](/tools/code) operation's TypeScript | No template syntax at all — it reads `input.secrets.NAME` |
| An `http` operation's `method`, a `transfer` destination | No — both are fixed values by design |

Writing `{{secrets.NAME}}` in a prompt or greeting fails validation:

```
the prompt cannot use {{secrets.CRM_API_KEY}} - a workspace secret is a
credential for tools to send, never text for the model
```

That refusal is the point of the whole feature, and the next section says why.

### Inside a `code` operation

A [`code`](/tools/code) operation has no template syntax, so a secret arrives as a property on the input object instead:

```typescript
export default async function handler(input) {
  const res = await fetch("https://api.example.com/orders", {
    headers: { Authorization: `Bearer ${input.secrets.CRM_API_KEY}` },
  });
  return await res.json();
}
```

Only the secrets a tool actually names are put in scope for that run — the tree is scanned for `{{secrets.NAME}}` templates and for `input.secrets.NAME` property access, and the workspace's other secrets are never sent to the sandbox.

### A single token keeps its type

A string that is **exactly one token** resolves to the value itself, with its type intact. A token inside a larger string is substituted as text:

```json
{
  "headers": { "Authorization": "Bearer {{secrets.CRM_API_KEY}}" },
  "body": { "token": "{{secrets.CRM_API_KEY}}" }
}
```

The header is a string with the key spliced in. The body's `token` is the stored value as-is, unquoted and unmodified.

## A missing name fails loudly

<Warning>
**An empty string is never substituted for a missing credential.** A `{{secrets.NAME}}` that resolves to nothing raises `secret 'NAME' does not exist` and the operation fails. It does not send an unauthenticated request and hope.
</Warning>

That is enforced twice:

- **At publish.** A tool referencing a secret the workspace does not have is a publish error, so the mistake is caught before anything is live. The same check runs on an inline MCP server's URL and headers.
- **At delete.** A secret something still references cannot be deleted, so a publish-time check cannot be undone afterwards. See [deleting one](#deleting-one).

## Rotating a value

Store the same name again. `POST /v1/secrets` is an upsert: the value is replaced, the original creator attribution is kept, and nothing that references the name has to change. Tools pick the new value up on their next run — there is no republish and no cache to clear.

There is no versioning and no undo. The previous value is gone the moment the new one lands.

## Deleting one

`DELETE /v1/secrets/{secret_id}`, ADMIN only. A secret that anything still references is refused with a `409` that names each one:

```
secret 'CRM_API_KEY' is used by tool 'lookup_order', integration 'CRM' — remove it there before deleting it
```

What counts as a reference:

- **A tool's draft or published version.** Edit the tool and publish it without the secret.
- **An older tool version a live agent or task still runs.** Publishing an agent pins its tools, so the tool's own republish is not enough — the message names the agent to republish too. See [the pin rule](/tools/testing-and-publishing#the-pin-rule-from-the-tools-side).
- **An integration or carrier account** whose credentials, MCP URL or headers name it. Point it at another secret, or delete it.

Older tool versions nothing runs do not block the delete.

If a tree still meets a missing secret at runtime — an agent rolled back onto a version that names one — the tool fails before any operation runs, the model is handed the same apology as any other aborted tool, and `tool.failed` fires.

## Plaintext is promoted automatically

[Integrations](/integrations/connecting) and [carrier accounts](/telephony/carrier-accounts) accept a credential field in either form:

- **An existing reference**, `{{secrets.RESEND_API_KEY}}`. The name has to exist, or the request is refused with `secret 'RESEND_API_KEY' does not exist`.
- **Raw plaintext.** It is written into the secrets store under a sensible default name — `RESEND_API_KEY` for a Resend key, say — and only the reference is stored on the integration row.

If the preferred name is already taken, a suffixed variant is allocated (`RESEND_API_KEY_a91c`) rather than overwriting the secret that is there. An existing credential another tool depends on is never clobbered by someone connecting an integration.

Either way, **plaintext is never stored on the integration or carrier row**. The row holds a reference; the value lives in one place, encrypted, with one way to rotate it.

## Why a credential must never be a variable

The other template roots are visible to the model and can be read aloud.

`{{vars.name}}` is substituted into the system prompt the model reads. `{{userdata.field}}` is session state the model reads, tools write, and the agent may repeat back to a caller. A model that can see a value can say it, put it in a summary, or pass it to a tool you did not intend.

A secret is different in kind: it is resolved by the runtime, inside the operation, on the way out to your API. **The model never sees it.** It cannot be repeated, cannot be leaked into a transcript, and does not appear in a call's stored request payloads.

So: an API key, a bearer token, a signing secret or a password is a secret. A customer's account number, a tenant id, a base URL for the environment this agent serves — those are [variables](/agents/variables). If a value would be damaging in a transcript, it is a secret.
