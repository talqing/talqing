Every number on this page is enforced in code. Where a limit has both a default and a ceiling, both are given: the default is what you get if you say nothing, the ceiling is the highest value the platform will accept.

## Agents

| Limit | Value |
| --- | --- |
| Agent `name` | At least 1 character. **No maximum** |
| `prompt`, `greeting` | **No length limit** |
| Tools, MCP servers, handoff targets per agent | **No count limit** |
| [FAQs](/agents/faqs) attached to one agent or task | 10 |
| Members in an [agent team](/teams/agent-teams-on-a-call) | 10 |
| Handoffs executed during one call | 25. Past that the agent cannot pass the caller on again |
| [Analysis](/observability/call-analysis) fields | 25 |
| Analysis field name | Lowercase, `^[a-z][a-z0-9_]{0,39}$` — 40 characters |
| `handoffs[].recent_turns` | 1–10 |
| `conversation.summary_limit` | At least 1. No maximum |
| TTS `speed` | 0.5–2.0, default 1.0 |
| ElevenLabs `stability`, `similarity_boost` | 0.0–1.0 |
| Noise cancellation `enhancement_level` | 0.0–1.0, default 0.8 |
| `min_silence_duration` | At least 0.25 s, default 0.5 s |

There is no size limit on an agent config, or on a whole definition sent inline on a call request. A [call batch](/telephony/batch-calling) stores its plan on every call it places, so keep a batch's inline definitions small — attach an FAQ there by `faq_id`.

A [`code`](/tools/code) operation runs on an isolated service, not in the call worker.

| Limit | Value |

| `console.log` output kept | 100 lines, each truncated at 2,000 characters |

## Calls

These are platform limits. **None of them is configurable per workspace**; the call duration can only be lowered, per agent.

| Limit | Value |
| --- | --- |
| Maximum call duration | **3 hours**, then the call is ended — on phone, web and media-stream calls alike. An agent can set a lower limit with [`max_duration_seconds`](/agents/silence-and-call-length) |
| Ring timeout | 60 s — how long a callee's phone rings on an outbound call |
| Media timeout | 120 s of dead audio before the leg is dropped |
| Chat inactivity timeout | None. A chat stays open until the agent's `end_call` or `POST /v1/chats/{id}/end` |
| Chat message wait | 120 s, then `POST /v1/chats/{id}/messages` returns `status: "running"`. A `stream: true` request has no cap |
| Chat token lifetime | 1 hour |
| Warm-transfer briefing | 90 s |
| Client `userdata` RPC payload | 16 KB |
| Post-call analysis | Skipped on a call with fewer than 2 user turns |

The one ring window you *can* set is a [`transfer`](/tools/transfer) operation's `ringing_timeout`, 5–120 s.

## Pagination

Every list endpoint takes `limit` and `offset` and returns `{ items, has_more, limit, offset }`. **There is no single platform-wide page size** — the ceiling is per endpoint:

| Ceiling | Endpoints |
| --- | --- |
| 200, default 200 | Agents, tools, tasks, secrets, calls, webhooks, credit ledger, telephony accounts, numbers, integrations, triggers, tokens, members |
| 200, default 100 | Conversations, workspaces |
| 200, default 50 | Task runs, email batches, call batches, webhook deliveries |
| **500**, default 200 | Conversation items |
| 100, default 100 | Catalog voices |

`offset` has no ceiling. There is no cursor and no total count — `has_more` is computed by fetching one extra row. See [pagination](/api-reference/pagination).

## Two limits that do not exist

Both of these come up in evaluation, so here they are stated plainly rather than left for you to discover.

### There is no general API rate limit

Nothing throttles inbound requests to the API. There is no per-token, per-workspace or per-IP quota, no `429` from the platform, and no `Retry-After` header to read. A `429` you see came from one of *your* providers being relayed, not from us.

That is the current state, not a promise about the future. Build a client that behaves reasonably rather than one that relies on being stopped.

### There are no concurrency, spend or duration caps you can configure

- **No concurrency cap.** Nothing limits how many calls a workspace runs at once. The only concurrency controls in the product are `max_concurrency` on a call batch and `draft_concurrency` on an email batch (1–10), each of which governs that one batch and nothing else. Two batches at 10 dial 20 at a time. Email **sending** has no concurrency at all — it is serial, paced by `send_gap_seconds`.
- **No spend cap.** There is no budget, no maximum monthly charge and no hard stop. The `low_balance_threshold` on your [credit balance](/get-started/pricing-and-credits) is a warning at $2 and blocks nothing — the only thing that stops new calls is the balance actually reaching zero.
- **No configurable call-duration cap.** The 3-hour maximum above is platform-wide and cannot be lowered for a workspace, an agent or a call. If you need a call to end sooner, do it in the agent: an [`end_call`](/tools/end-call) operation the model can reach, or a prompt that closes the conversation.
