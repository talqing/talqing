description: "Create, publish and talk to a text agent in one script, in TypeScript or Python."

This quickstart is code only — no dashboard. One script creates a text agent, publishes it, starts a chat, sends a message, prints the reply and ends the chat. It runs in about a minute.

A text agent needs **only a language-model key** — no speech-to-text, no text-to-speech. It costs what your own LLM key was charged, plus Talqing's platform fee of **$0.0001 per answered message**.

## Before you start

<Steps>
  <Step title="Get a personal access token">
    In the dashboard, go to **Organization → API Tokens** and create one. The full value is shown once. Export it as `TALQING_API_KEY`.
  </Step>
  <Step title="Add one LLM provider key">
    On the **BYOK** page, add a key for the provider whose model you are about to use — OpenAI in this example. Talqing holds no provider keys of its own, so publishing an agent whose provider has no key is refused with `no OpenAI API key for this workspace - add one under BYOK`. See [provider keys](/get-started/provider-keys).
  </Step>
  <Step title="Pick a region">
    `https://api.in.talqing.com` (India) or `https://api.us.talqing.com` (United States). The agent you create belongs to that region. Your token works against both. See [regions](/get-started/regions).
  </Step>
</Steps>

## The whole script

<CodeGroup>
```typescript TypeScript
import { randomUUID } from "node:crypto";
import { TalqingClient } from "@talqing/sdk";

const token = process.env.TALQING_API_KEY;
if (!token) throw new Error("TALQING_API_KEY is required");

const talqing = new TalqingClient({
  baseUrl: "https://api.in.talqing.com",
  token,
});

// 1. Create the agent.
const agent = await talqing.agents.create({
  createAgentRequest: {
    config: {
      name: "Northwind support",
      channel: "text",
      prompt: [
        "You are the support assistant for Northwind Tools, an online hardware store.",
        "Answer questions about orders, delivery and returns.",
        "Ask for the order number before you discuss a specific order.",
        "If you do not know something, say so plainly instead of guessing.",
        "Keep replies to two or three sentences.",
      ].join(" "),
      llm: { provider: "openai", model: "gpt-5.6-luna" },
    },
  },
});

// 2. Publish it. Nothing can talk to a draft.
await talqing.agents.publish({ agent_id: agent.id });

// 3. Start a chat. `contact_key` is your own id for the person.
const chat = await talqing.chats.create({
  createChatRequest: { contact_key: "user-42", agent_id: agent.id },
});

// 4. Say something. The reply comes back on this request.
const turn = await talqing.chats.messages.create({
  chat_id: chat.id,
  chatMessageRequest: {
    client_message_id: randomUUID(),
    message: "My order 10432 never arrived. What happens now?",
  },
});

if (turn.status !== "done") throw new Error(turn.error ?? `the turn ended ${turn.status}`);
for (const item of turn.items) {
  if (item.type === "message") console.log(item.text);
}

// 5. End the chat. Nothing else will: a chat has no inactivity timeout.
await talqing.chats.end({ chat_id: chat.id });
```

```python Python
import os
from uuid import uuid4

from talqing import Talqing

with Talqing(
    token=os.environ["TALQING_API_KEY"],
    base_url="https://api.in.talqing.com",
) as talqing:
    # 1. Create the agent.
    agent = talqing.agents.create(
        config={
            "name": "Northwind support",
            "channel": "text",
            "prompt": (
                "You are the support assistant for Northwind Tools, an online hardware store. "
                "Answer questions about orders, delivery and returns. "
                "Ask for the order number before you discuss a specific order. "
                "If you do not know something, say so plainly instead of guessing. "
                "Keep replies to two or three sentences."
            ),
            "llm": {"provider": "openai", "model": "gpt-5.6-luna"},
        }
    )

    # 2. Publish it. Nothing can talk to a draft.
    talqing.agents.publish(agent["id"])

    # 3. Start a chat. `contact_key` is your own id for the person.
    chat = talqing.chats.create(contact_key="user-42", agent_id=agent["id"])

    # 4. Say something. The reply comes back on this request.
    turn = talqing.chats.messages.create(
        chat["id"],
        client_message_id=str(uuid4()),
        message="My order 10432 never arrived. What happens now?",
    )

    if turn["status"] != "done":
        raise RuntimeError(turn["error"] or f"the turn ended {turn['status']}")
    for item in turn["items"]:
        if item["type"] == "message":
            print(item["text"])

    # 5. End the chat. Nothing else will: a chat has no inactivity timeout.
    talqing.chats.end(chat["id"])
```
</CodeGroup>

## What each call does

<Steps>
  <Step title="Create the agent">
    `POST /v1/agents` takes the **whole** config. Only `name` is required; `channel: "text"` is what removes the speech slots. `gpt-5.6-luna` is a cheap, fast general model — see the [full catalog](/agents/models) before picking another, because a provider or model that is not in it is refused.

    ```bash cURL
    curl -X POST https://api.in.talqing.com/v1/agents \
      -H "Authorization: Bearer $TALQING_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "config": {
          "name": "Northwind support",
          "channel": "text",
          "prompt": "You are the support assistant for Northwind Tools, an online hardware store. Answer questions about orders, delivery and returns. Ask for the order number before you discuss a specific order. If you do not know something, say so plainly instead of guessing. Keep replies to two or three sentences.",
          "llm": { "provider": "openai", "model": "gpt-5.6-luna" }
        }
      }'
    ```
  </Step>

  <Step title="Publish it">
    `POST /v1/agents/{agent_id}/publish` freezes the draft as version 1. Starting a chat with an unpublished agent is refused with `publish 'Northwind support' before calling it`. Publish is also where the provider-key check runs.

    ```bash cURL
    curl -X POST "https://api.in.talqing.com/v1/agents/$AGENT_ID/publish" \
      -H "Authorization: Bearer $TALQING_API_KEY"
    ```
  </Step>

  <Step title="Start a chat">
    `POST /v1/chats` starts a chat between a contact and this agent, and returns its `id`. `contact_key` is your own stable id for the person, up to 256 characters; leave it out and the chat gets a single-use one. Nothing is sent yet.

    ```bash cURL
    curl -X POST https://api.in.talqing.com/v1/chats \
      -H "Authorization: Bearer $TALQING_API_KEY" \
      -H "Content-Type: application/json" \
      -d "{\"contact_key\": \"user-42\", \"agent_id\": \"$AGENT_ID\"}"
    ```
  </Step>

  <Step title="Send a message">
    `POST /v1/chats/{id}/messages` sends the message and **answers with the agent's reply**. `client_message_id` is a UUID you generate; re-sending with the same one returns the same turn rather than posting twice.

    The response carries `status` (`done`, `error`, `canceled` or `running`) and `items`. Expect **several** items rather than one when the agent calls tools: a `function_call` and a `function_call_output` land beside the `message`.

    ```bash cURL
    curl -s -X POST "https://api.in.talqing.com/v1/chats/$CHAT_ID/messages" \
      -H "Authorization: Bearer $TALQING_API_KEY" \
      -H "Content-Type: application/json" \
      -d "{
        \"client_message_id\": \"$(uuidgen | tr 'A-Z' 'a-z')\",
        \"message\": \"My order 10432 never arrived. What happens now?\"
      }" \
    | jq -r '.items[] | select(.type == "message") | .text'
    ```
  </Step>

  <Step title="End the chat">
    `POST /v1/chats/{id}/end`. A chat stays open until this, or the agent's own `end_call` tool, ends it — and its analysis and `session.completed` webhook only happen then.

    ```bash cURL
    curl -X POST "https://api.in.talqing.com/v1/chats/$CHAT_ID/end" \
      -H "Authorization: Bearer $TALQING_API_KEY"
    ```
  </Step>
</Steps>

## Streaming the reply

Add `"stream": true` to the message and the same request answers as server-sent events: `assistant.started`, `assistant.delta` and `assistant.completed` as the reply is generated, an `item.created` for each item the turn produces, then one `turn.result` carrying the same body the JSON response would. **`assistant.delta` frames append — they are not cumulative.**

```bash cURL
curl -N -X POST "https://api.in.talqing.com/v1/chats/$CHAT_ID/messages" \
  -H "Authorization: Bearer $TALQING_API_KEY" \
  -H "Content-Type: application/json" \
  -d "{
    \"client_message_id\": \"$(uuidgen | tr 'A-Z' 'a-z')\",
    \"message\": \"And how long do returns usually take?\",
    \"stream\": true
  }"
```

To chat from a browser, your server mints a token for the chat and the page uses `TalqingChat` from `@talqing/client`. See [chats](/channels/text-conversations#from-a-browser).
